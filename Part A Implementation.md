# DDPM / DDIM implementation notes (A -> B)

This document explains what was implemented for the midterm (DDPM + DDIM), file by file and function by function, and why each choice was made. It also lists the interface B needs for `train.py` and `inference.py`. Everything here is in `schedulers/scheduling_ddpm.py`, `schedulers/scheduling_ddim.py` and `pipelines/ddpm.py`. The script `Claude_test_A.py` checks all of it in one run; please run it after pulling.

## The big picture

A diffusion model has two halves. The **forward process** takes a clean image x0 and mixes in Gaussian noise. We never train this part, because it has a closed form: at timestep t, x_t = sqrt(abar_t) * x0 + sqrt(1 - abar_t) * eps, where eps is standard normal noise and abar_t is a cumulative product from a fixed noise schedule. The **reverse process** is learned: the UNet takes x_t and t and predicts the noise eps that was mixed in. Training is therefore a plain regression: pick a random t, noise an image with a noise we chose ourselves, ask the UNet to predict that noise, take the MSE. Generating an image means starting from pure noise and repeatedly using the UNet's prediction to step from x_t to x_{t-1} until we reach x_0. The scheduler classes own all the math around those two processes (the schedule, adding noise, taking a reverse step). The UNet only predicts noise, and the pipeline just loops.

## File 1: `schedulers/scheduling_ddpm.py`

**`__init__` (the schedule).** `betas` is `torch.linspace(beta_start, beta_end, num_train_timesteps)`, i.e. T = 1000 values rising linearly from 1e-4 to 0.02 (the original DDPM setting). `alphas = 1 - betas`, and `alphas_cumprod = torch.cumprod(alphas, dim=0)`; this is abar_t, the fraction of the original signal left at step t. Sanity values: abar_0 is about 0.9999 (almost no noise) and abar_999 is about 4e-5 (almost pure noise). `timesteps` defaults to T-1 ... 0 as int64. Two things matter for B. First, the buffer names `betas`, `alphas`, `alphas_cumprod` must stay exactly as they are, because checkpoints save `scheduler.state_dict()` and loading is strict; `timesteps` is registered with `persistent=False` so it never enters the checkpoint (inference rebuilds it for its own step count). Any extra precomputed tensor must also be `persistent=False`. Second, `train.py` defaults `beta_start` to 2e-4 while the scheduler's own default is 1e-4, so please set `beta_start: 0.0001` explicitly in `ddpm.yaml`. Other `beta_schedule` names raise `NotImplementedError`; that is where a cosine schedule can go for the advanced section.

**`set_timesteps(n)`.** Chooses which timesteps to visit at inference. The stride is `T // n`, and the timesteps are `0, stride, 2*stride, ...` reversed. For n = 200 that gives 995, 990, ..., 5, 0. Note this only works cleanly when n divides T (1000, 500, 200, 100, 50...); for other values the first step would start below T-1. It assigns `self.timesteps` as a tensor on the requested device.

**`previous_timestep(t)`.** Returns `t - T // n`. When no inference step count has been set, n falls back to T, so the stride is 1 and it is just `t - 1`. At the last step this goes negative (0 -> -1 or -5). That is deliberate: it is the signal for "the previous alpha-bar is 1", and it must not be clamped to 0, otherwise the final step would never reach a fully clean image.

**`_get_variance(t)`.** Returns sigma_t squared (a variance, not a standard deviation), the amount of noise to inject in a reverse step. With abar_prev = abar at `previous_timestep(t)` (taken as 1.0 when prev is negative), the effective beta over the jump is `current_beta_t = 1 - abar_t / abar_prev`. With stride 1 that equals the original beta_t; with stride 5 it is the combined noise of the 5 skipped steps, which is what lets DDPM sampling run with fewer steps. The posterior variance is `(1 - abar_prev) / (1 - abar_t) * current_beta_t` (Eq. 7 of the DDPM paper), clamped at 1e-20 so it is never exactly zero or `-inf` under a log. `variance_type="fixed_small"` returns this value; `"fixed_large"` returns `current_beta_t` (with the paper's small-variance hack at t = 0). The two options are the upper and lower bounds on the reverse-step variance, and the paper shows both work; we use `fixed_small`.

**`add_noise(x0, noise, timesteps)`.** The training-time forward process: `sqrt(abar_t) * x0 + sqrt(1 - abar_t) * noise`. The key detail is `alphas_cumprod[timesteps]`, which picks one value per image (shape (B,)); the `while` loop then reshapes it to (B,1,1,1) so it broadcasts over channels and pixels. The two coefficients are squared-weights that sum to 1, so x_t keeps roughly unit variance at every t. This is also what the loss formula in the paper (Eq. 14 / Eq. 6 of the writeup) feeds into the UNet. Interface: `timesteps` is a LongTensor of shape (B,) with values 0 ... T-1, so B should use `torch.randint(0, T, (B,))` (the upper bound is exclusive, and the UNet's time-embedding table has exactly T rows).

**`step(model_output, t, sample, generator)`.** One reverse step x_t -> x_{t-1}. (1) Compute abar_t, abar_prev and the jump's alpha and beta. (2) Turn the predicted noise into a guess of the clean image: `x0_hat = (x_t - sqrt(1 - abar_t) * eps_pred) / sqrt(abar_t)`. (3) Clip x0_hat to [-clip_range, clip_range] if `clip_sample` (it should stay in image range; this stops errors compounding). (4)-(5) The posterior mean is a weighted blend of x0_hat and x_t, with coefficients `sqrt(abar_prev) * beta / (1 - abar_t)` and `sqrt(alpha) * (1 - abar_prev) / (1 - abar_t)` (Eq. 7). At the last step abar_prev = 1, so the second coefficient is 0 and the first is 1: the output is exactly x0_hat. (6) Add `sqrt(variance) * z` with fresh Gaussian noise z, except at t = 0. The noise is there because the reverse step is a *sample* from a Gaussian whose mean the model provides; skipping it would give the blurry average of every image consistent with x_t, and it is what makes DDPM sampling stochastic.

## File 2: `pipelines/ddpm.py` (`__call__`)

The sampling loop. Start from `randn_tensor(image_shape)`, where the shape comes from `unet.input_ch` and `unet.input_size` (so B must pass the *unwrapped* UNet, `unet_wo_ddp`, not the DDP wrapper). Call `self.scheduler.set_timesteps(num_inference_steps, device=device)` (a method call, not an assignment). Then for each `t` in `scheduler.timesteps`: `model_output = unet(image, t, c=c)` and `image = scheduler.step(model_output, t, image, generator=generator)`. Pass the same `generator` to both the initial noise and `step`, so a seed fully reproduces a sample. At the end `(image / 2 + 0.5).clamp(0, 1)` maps [-1, 1] to [0, 1] and the existing helper converts to PIL images.

The class-conditioning (CFG) branches and the VAE branch are already written in the same function, but they stay inert unless `classes` / `vae` are passed, and they are **not part of the midterm and not tested yet**: they build the unconditional embedding from index `class_embedder.num_classes`, run the UNet on a doubled batch `[uncond, cond]`, combine with `eps_uncond + w * (eps_cond - eps_uncond)`, and for latents divide by 0.1845 before `vae.decode`. For unconditional runs, do **not** pass `guidance_scale` (the provided helper raises if a scale is given without classes).

## File 3: `schedulers/scheduling_ddim.py`

`DDIMScheduler` subclasses `DDPMScheduler`, so it reuses the schedule, `add_noise`, `set_timesteps` and `previous_timestep`. Its constructor asserts that `num_inference_steps` is given and calls `set_timesteps` immediately, so it must be built with that argument (the pipeline later calls `set_timesteps` again with the same value). Two methods differ.

**`_get_variance(t)`.** Same expression as DDPM's posterior variance, written as `(1 - abar_prev)/(1 - abar_t) * (1 - abar_t/abar_prev)`, with no clamp and no `variance_type` switch. This is DDIM's sigma_t squared at eta = 1. In DDIM the variance is not a modeling choice; it is a dial (see below), so the fixed-small/fixed-large option disappears.

**`step(...)`.** Same first moves as DDPM (x0_hat, clip), then DDIM's update: `x_{t-1} = sqrt(abar_prev) * x0_hat + sqrt(1 - abar_prev - sigma^2) * eps_pred + sigma * z`, with `sigma = eta * sqrt(variance)`. The middle term is the "direction pointing to x_t": the part of the noise budget not spent on fresh randomness. The random term is only added when `eta > 0`. If `clip_sample` is on, `eps_pred` is recomputed from the clipped x0_hat so that x0_hat and eps stay consistent with each other; DDPM does not need that because it only uses x0_hat afterwards. The default `eta = 0`, and the pipeline calls `step` without an `eta` argument, so pipeline sampling with DDIM is deterministic. (An eta ablation would need an `eta` argument added to the pipeline.)

## DDPM vs. DDIM in one paragraph

Both samplers use the **same trained UNet** and the same noise prediction; they differ only in the `step` rule. DDPM's reverse step is derived from the one-step Markov chain of the forward process: every step is a Gaussian sample with fresh noise, and the derivation only holds for single steps, so it needs roughly 1000 of them (we get away with a coarser stride using the "jump" betas, with some quality loss). DDIM observes that the training loss only depends on the marginals q(x_t | x0), not on the one-step transitions, so many different (non-Markovian) reverse processes share the same marginals and work with the same network. They form a family indexed by sigma_t: with eta = 1 the family member is exactly DDPM, and with eta = 0 there is no randomness at all, so the same starting noise always gives the same image, and the update is valid for any earlier timestep, which is why it can skip, e.g. 200 steps instead of 1000, with little quality loss. Cost scales with the number of UNet evaluations, so 200 steps is about 5x faster. Expected result for the report: DDIM at 200 steps has FID close to DDPM at 1000 steps, with degradation at very few steps (10-20). `midterm_checks.py` includes a test that DDIM with eta = 1 and 1000 steps reproduces the DDPM step exactly, which is the numerical version of this statement.

## What B needs from this (interface summary)

- Noise and timesteps: `noise = torch.randn_like(images)`, `timesteps = torch.randint(0, T, (B,), device=device).long()`.
- Loss: `noisy = scheduler.add_noise(images, noise, timesteps)`; `pred = unet(noisy, timesteps, c=class_emb)`; MSE between `pred` and `noise`.
- Build schedulers with keyword arguments matching the argparse names (`num_train_timesteps`, `num_inference_steps`, `beta_start`, `beta_end`, `beta_schedule`, `variance_type`, `prediction_type`, `clip_sample`, `clip_sample_range`). DDIM needs `num_inference_steps`.
- Pipeline: `DDPMPipeline(unet_wo_ddp, scheduler_wo_ddp, vae=vae, class_embedder=class_embedder_wo_ddp)`; call `pipeline(batch_size=..., num_inference_steps=args.num_inference_steps, generator=generator, device=device)`. The validation block runs the pipeline before `save_checkpoint`, so a bug there costs an epoch; run one tiny end-to-end pass before the long run.
- Config: set `beta_start: 0.0001`, `beta_end: 0.02`, `beta_schedule: linear`, `num_train_timesteps: 1000`; `num_inference_steps` 1000 for plain DDPM and 200 for DDIM.
- Checkpoint keys: `betas`, `alphas`, `alphas_cumprod` only. Tell A before adding scheduler buffers.

## Pitfalls we hit (so you don't)

- `register_buffer` only accepts tensors: NumPy arrays, lists and `reversed(...)` iterators all fail.
- `alphas_cumprod[t]` must be indexed by the timesteps tensor; using the whole table gives shape (1000,...) and a broadcast error.
- `sqrt(1 - abar_t)` is not `sqrt(abar_t) - 1`. The second coefficient in `add_noise` has to be computed from `1 - alphas_cumprod[timesteps]`, and a wrong version trains silently on garbage, which is why `midterm_checks.py` tests the formula against a hand computation and also checks the unit variance.
- In Jupyter, reloading modules in the wrong order (DDIM before DDPM) gives `super(type, obj)` errors; restart the kernel instead.
- Clipping x0 to [-1, 1] makes sense in pixel space. For latent DDPM the latents are not bounded to [-1, 1], so plan to try `clip_sample: false` there (a good ablation for the report).
